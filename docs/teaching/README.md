# 电机驱动板教学路线

这套文档把当前的正式底盘固件拆成可讲、可做、可验收的学习路径。它不是第二套固件，
也不改变正式工程的控制链；每一课都应从下到上解释当前工程中已经存在的一个能力。

## 阅读顺序

1. [01：板卡与主控资源](01_board_and_mcu.md)
2. [02：Keil 与 OpenOCD 开发环境](02_toolchains.md)
3. [03：最小 Hello World](03_hello_world.md)
4. [04：当前固件已经实现什么](04_current_capabilities.md)
5. [05：从 Hello World 逐步重建到底盘](05_learning_path.md)

现有正式固件的完整运行链和人工验收项见[当前架构](current_architecture.md)。

## 课程边界

- 主控：AT32F456RCT7，Cortex-M4；当前工程使用寄存器/厂商标准外设库，不切换到 HAL。
- 生产代码分层固定为 `drivers → services → app`；教学例程也按这个顺序引入。
- 上位机负责路线、RFID、任务和绝对定位；电机板只执行短 TTL 的 `v/ω`、差速、速度环、相对里程计和本地安全停车。
- 电机、PWM、防撞条和电气保护属于真实硬件。学生实验从无电机输出的 Hello World 开始，不能用示例代码绕过现有停车和保护逻辑。

## 资料可信度

本文档优先采用三类证据：当前 Keil 工程、当前正式源码、已核对的新版网表摘要。
仓库内 `hardware/电机驱动板.json` 属于旧版板卡资料，主控型号与当前工程不一致；
它只能作为历史参考，不能据此新增当前板卡的引脚结论。

## 文档与代码的关系

课程前 3 章只建立环境和最小可观察程序，不修改 `src/app/main.c`。从第 4 章开始，
学生阅读当前模块；第 5 章规定每次只引入一个硬件边界，并复用正式工程的构建与验证入口。
