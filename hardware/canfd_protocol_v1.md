# AGV 电机驱动板 CAN FD 历史协议 V1（已弃用）

> 本文件仅保留 2026-08-11 单板联调时使用的历史私有协议，不能再用于配置当前整车或上位机。当前固件遵循 [`AGV_CANopen_FD_Protocol_V0.2.md`](../../../docs/AGV_CANopen_FD_Protocol_V0.2.md)，总线参数为仲裁段 500 kbit/s、数据段 4 Mbit/s、开启 BRS；整车静态验证见 [`canfd_vehicle_4m_validation_2026-08-15.md`](canfd_vehicle_4m_validation_2026-08-15.md)，500 kbit/s / 1 Mbit/s 记录仍作为回退基线。

联调通过记录见 [`canfd_motor_integration_test_2026-08-11.md`](canfd_motor_integration_test_2026-08-11.md)。

当前代码与协议设计审查问题见 [`canfd_code_design_review_2026-08-13.md`](canfd_code_design_review_2026-08-13.md)。该文档中的 P0/P1 项关闭前，本协议仅作为单板架空联调基线，不作为整车安全准入结论。

## 1. 总线参数与字节序

- CAN FD ISO，11 位标准帧。
- 仲裁段 1 Mbit/s，数据段 4 Mbit/s，开启 BRS。
- 多字节字段均为小端序，有符号数使用二进制补码。
- 每帧最后 2 字节为 CRC16-CCITT：初值 `0xFFFF`，多项式 `0x1021`，计算范围不含 CRC 字段。
- 当前节点号为 1。设备 ID 由 MCU UID 计算，用于 ACK 中识别电机板。

## 2. CAN ID 分配

| CAN ID | 方向 | 长度 | 名称 | 优先级/周期 |
| --- | --- | ---: | --- | --- |
| `0x080` | 主控到板端 | 16 | ESTOP 广播 | 最高优先级，不依赖会话 |
| `0x091` | 主控到板端 | 16 | STOP/CLEAR_FAULT/RESET_ODOM | STOP 不依赖会话 |
| `0x101` | 主控到板端 | 16 | 主控心跳与会话 | 建议 100 ms，运行态超时 300 ms |
| `0x111` | 主控到板端 | 24 | 速度流命令 | V1 预留，当前固件显式拒绝 |
| `0x121` | 主控到板端 | 32 | 本地坐标 GOTO | 当前只允许直行 |
| `0x181` | 板端到主控 | 16 | 命令 ACK/任务事件 | 紧急队列 |
| `0x201` | 板端到主控 | 24 | 驱动状态 | 20 ms |
| `0x211` | 板端到主控 | 32 | 里程计状态 | 50 ms |
| `0x221` | 板端到主控 | 32 | 电机状态 | 100 ms |
| `0x231` | 板端到主控 | 24 | 安全状态/事件 | 正常 500 ms、故障 100 ms、变化立即上报 |

## 3. 主控命令帧

### 3.1 心跳 `0x101`，16 字节

| 字节 | 类型 | 含义 |
| --- | --- | --- |
| 0 | `u8` | 协议版本，固定 1 |
| 1 | `u8` | 保留，填 0 |
| 2..3 | `u16` | 心跳序号，不能为 0 |
| 4..7 | `u32` | 会话 ID，不能为 0；主控每次启动随机生成 |
| 8..11 | `u32` | 主控运行时间 ms |
| 12..13 | - | 保留，填 0 |
| 14..15 | `u16` | CRC16 |

新会话替换正在运动的旧会话时，板端先本地停车并锁存通信故障。运动命令执行期间超过 300 ms 未收到有效心跳，也会本地停车、锁存 `COMM_TIMEOUT` 并上报安全事件。

### 3.2 控制 `0x091`，16 字节

| 字节 | 类型 | 含义 |
| --- | --- | --- |
| 0 | `u8` | 协议版本 1 |
| 1 | `u8` | 操作码：1 STOP，2 CLEAR_FAULT，3 RESET_ODOM |
| 2..3 | `u16` | 命令序号 |
| 4..7 | `u32` | 会话 ID；STOP 可不匹配，其他操作必须匹配 |
| 8..13 | - | 保留，填 0 |
| 14..15 | `u16` | CRC16 |

`CLEAR_FAULT` 不是自动恢复：只有防撞输入全部释放并稳定 100 ms、IMU 正常且无活动任务时才接受。`RESET_ODOM` 不清除任何故障。

### 3.3 急停 `0x080`，16 字节

| 字节 | 类型 | 含义 |
| --- | --- | --- |
| 0 | `u8` | 协议版本 1 |
| 1 | `u8` | 急停原因码 |
| 2..3 | `u16` | 命令序号 |
| 4..7 | `u32` | 发送方会话/来源标识 |
| 8..11 | `u32` | 发送方时间戳 ms |
| 12..13 | - | 保留，填 0 |
| 14..15 | `u16` | CRC16 |

急停和 STOP 不依赖当前会话，也不经过普通运动命令队列；急停会锁存故障，STOP 只停车/保持制动。

### 3.4 本地坐标命令 `0x121`，32 字节

| 字节 | 类型 | 含义 |
| --- | --- | --- |
| 0 | `u8` | 协议版本 1 |
| 1 | `u8` | 保留，填 0 |
| 2..3 | `u16` | 命令序号 |
| 4..7 | `u32` | 会话 ID |
| 8..11 | `i32` | X，mm |
| 12..15 | `i32` | Y，mm |
| 16..19 | `i32` | 航向角，0.01 度 |
| 20..21 | `u16` | 速度，mm/s |
| 22..29 | - | 保留，填 0 |
| 30..31 | `u16` | CRC16 |

当前运动控制器仅接受 `X=300..3000 mm`、`Y=0`、`yaw=0`、`speed=50..100 mm/s` 的前进命令。倒车、横移、转向和速度流要在整车运动学及反向里程计验证完成后再开放。

## 4. 板端上报帧

### 4.1 ACK/事件 `0x181`，16 字节

| 字节 | 类型 | 含义 |
| --- | --- | --- |
| 0 | `u8` | 协议版本 1 |
| 1 | `u8` | 状态：0 RECEIVED，1 ACCEPTED，2 COMPLETED，3 CANCELED，4 DUPLICATE，5 REJECTED，6 FAULT |
| 2..3 | `u16` | 对应命令序号 |
| 4..7 | `u32` | 设备 ID |
| 8 | `u8` | 命令类型 |
| 9 | `u8` | 错误码 |
| 10..11 | `u16` | 当前故障位 |
| 12 | `u8` | 当前状态机状态 |
| 13 | `u8` | 节点号 |
| 14..15 | `u16` | CRC16 |

错误码：0 无错误，1 版本，2 序号，3 范围，4 格式，5 不支持，6 忙，7 CRC，8 长度，9 会话，10 故障锁定，11 超时，12 CAN Bus-Off。

### 4.2 安全状态/事件 `0x231`，24 字节

| 字节 | 类型 | 含义 |
| --- | --- | --- |
| 0 | `u8` | 协议版本 1 |
| 1 | `u8` | 状态机状态 |
| 2..3 | `u16` | 状态帧序号 |
| 4..7 | `u32` | 板端运行时间 ms |
| 8 | `u8` | 防撞输入原始电平位图 |
| 9 | `u8` | 当前有效防撞位图 |
| 10 | `u8` | 防撞锁存位图 |
| 11 | `u8` | 安全来源：bit0 防撞，bit1 急停，bit2 通信超时，bit3 CAN 链路/Bus-Off，bit4 IMU，bit5 运动故障 |
| 12..13 | `u16` | 故障位图 |
| 14..15 | `u16` | 活动/最近命令序号 |
| 16..17 | `u16` | 距离最近有效心跳的时间 ms；无会话为 `0xFFFF` |
| 18 | `u8` | CAN 状态：bit0 Bus-Off，bit1 Error Passive，bit2 Error Warning，bit3 RX Overflow |
| 19 | `u8` | RX 丢帧计数低 8 位 |
| 20..21 | - | 保留，填 0 |
| 22..23 | `u16` | CRC16 |

防撞方向位：bit0 右，bit1 左，bit2 后，bit3 前。硬件为外部上拉、开关接地，所以原始位 0 表示按下；`active_mask` 和 `latched_mask` 中的 1 表示发生碰撞。

故障位：`0x0001` 急停，`0x0002` IMU，`0x0004` 运动控制，`0x0008` 防撞，`0x0010` 通信超时，`0x0020` CAN 链路发送失败或 Bus-Off。发送帧只有得到硬件成功确认后才从软件队列移除；无 ACK、发送卡住或 Bus-Off 会本地停车并锁存 `0x0020`，完整重置 CAN3，恢复后优先补报安全事件。

防撞按下沿由 EXTI 中断先锁存，控制周期内立即保持电机制动并取消活动任务。即使输入很快释放，`latched_mask` 和故障仍保持；状态变化立即走紧急发送队列，故障期间每 100 ms 复报，直到有效 `CLEAR_FAULT`。

### 4.3 驱动状态 `0x201`，24 字节

字段依次为：版本 `u8`、状态 `u8`、帧序号 `u16`、运行时间 `u32`、活动命令序号 `u16`、故障位 `u16`、左右目标转速 `i16×2`、左右实测转速 `i16×2`（转速均为 rpm×100）、活动命令来源 `u8`、防撞锁存位 `u8`、CRC16。

### 4.4 里程计状态 `0x211`，32 字节

字段依次为：版本、状态、帧序号、运行时间、X/Y `i32 mm`、航向 `i32 0.01°`、线速度 `i16 mm/s`、角速度 `i16 0.01°/s`、质量 `u8`、保留、CRC16。

### 4.5 电机状态 `0x221`，32 字节

字段依次为：版本、状态、帧序号、运行时间、左右目标/实测转速 `i16`（rpm×100）、左右 PWM `i16`、左右累计编码器计数 `i32`、左右非法跳变计数低 8 位、CRC16。

## 5. 联调规则

1. 主控启动后生成非零随机会话 ID，先连续发送心跳，再下发需要会话的控制命令。
2. 命令序号在同一会话内递增；相同序号返回 DUPLICATE，旧序号返回 SEQUENCE 错误。
3. 主控不能因为防撞输入已释放就自行恢复运动，必须看到安全帧输入释放稳定，再发送 CLEAR_FAULT，并等待 ACCEPTED 和故障清零事件。
4. STOP、ESTOP、安全事件与 ACK 的优先级高于运动和周期遥测。
5. 上位机测试工具为 `tools/canfd_agv_test.py`；当前适配 WeActStudio USB2CANFDV1 的 gs_usb/candleLight FD 固件。

## 6. 指定距离行走命令

正式底盘固件下，可由电脑端保持心跳并下发指定距离：

```powershell
python tools\canfd_agv_test.py goto --distance-mm 500 --speed-mm-s 50
```

- 距离范围为 300..3000 mm，当前只允许正向直行；速度范围为 50..100 mm/s。
- 工具先读取 `0x231` 安全状态。只存在 `0x0020` CAN 链路故障且防撞未触发时，会在同一会话内自动清除；其他故障默认拒绝启动。
- 如已现场确认并需要尝试清除其他可恢复故障，显式增加 `--clear-faults`；防撞仍处于按下状态时不会清除。
- 收到 GOTO ACCEPTED 后，工具每 100 ms 发送心跳，输出 `0x211` 里程计和 `0x201` 驱动状态，直到收到 COMPLETED、CANCELED 或 FAULT。
- 主机等待超时或按下 Ctrl+C 时发送 STOP；USB/CAN 异常中断时，板端自身的 300 ms 心跳超时和 CAN 链路故障路径会保持制动。
