# AGV 车辆方位、超声波阵列位置与安全功能验证状态

日期：2026-08-15

> 2026-08-17 更新：四路防撞动态制动、车轮物理停止、P0 安全补丁和 CAN 紧急
> 结果队列压力回归均已完成。最新状态和固件哈希见
> [`chassis_p0_safety_and_bumper_regression_2026-08-17.md`](chassis_p0_safety_and_bumper_regression_2026-08-17.md)。
> 本文仍作为车辆坐标和超声波阵列 180° 位置映射的基准；下文 2026-08-15
> 的“待确认/未完成”状态仅表示当日快照。

本文固化当前车辆的机械方位基准、四块超声波阵列的 180° 位置修正、已完成的
实板验证以及仍未完成的项目。后续接线、节点配置、上位机显示和安全验收均以
本文的“当前/新位置”为准，不再沿用安装时的旧位置标签。

## 1. 车辆坐标与命名基准

- `前`：车辆车头方向，也是当前低速 `GOTO` 正方向。
- `后`：车辆车尾方向。
- `左/右`：操作人员面向车头时车辆自身的左侧和右侧。
- 底盘为左右两主动轮差速结构，前后为万向轮；不按麦克纳姆轮解释方向。
- 2026-08-15 架空实测确认：当前右主动轮的机械转向会使车辆向车头方向运动。

所有 `LeftFront/RightFront/RightRear/LeftRear`、防撞方向位和上位机方位显示都
必须使用上述车辆坐标，不能使用人员面对某块板时的局部左右。

## 2. 四块超声波阵列位置旋转 180°

### 2.1 已确认的物理事实

用户在 2026-08-15 现场确认：此前记录的四块超声波阵列位置整体相对车辆坐标
旋转了 180°。因此旧“左前”实际位于当前“右后”，其余三块按同一 180°
变换处理。

```text
                              车头

    当前左前 = 旧右后                         当前右前 = 旧左后
       0x06 -> 0x04                              0x07 -> 0x05

    当前左后 = 旧右前                         当前右后 = 旧左前
       0x05 -> 0x07                              0x04 -> 0x06

                              车尾
```

### 2.2 旧标签、旧地址与当前正确位置

超声波 GD32 工程仍采用标准语义：`0x04=左前`、`0x05=右前`、`0x06=右后`、
`0x07=左后`。地址和安装位保存在每块板的非易失配置页。因此应修改物理板的
非易失节点配置，不应交换协议常量或在上位机中增加反向补丁。

| 安装时旧标签 | 旧节点地址 | 当前正确位置 | 应重新配置为 | 配置位置参数 |
| --- | ---: | --- | ---: | --- |
| 旧左前 | `0x04` | 当前右后 | `0x06` | `RightRear` |
| 旧右前 | `0x05` | 当前左后 | `0x07` | `LeftRear` |
| 旧右后 | `0x06` | 当前左前 | `0x04` | `LeftFront` |
| 旧左后 | `0x07` | 当前右前 | `0x05` | `RightFront` |

协议常量证据：
[`sonic-range-gd32/User/agv_rs485_protocol.h`](../../sonic-range-gd32/User/agv_rs485_protocol.h)。
节点配置工具：
[`sonic-range-gd32/scripts/configure-node.ps1`](../../sonic-range-gd32/scripts/configure-node.ps1)。

### 2.3 后续重配置要求

1. 一次只连接一块超声波板，或明确指定唯一调试器序列号，防止写错配置页。
2. 根据上表对该物理板运行 `configure-node.ps1 -Position <位置>`。
3. 每次写入必须看到 OpenOCD 擦写成功、`verify_image` 成功和复位运行成功。
4. 四块板完成后，以 `0x04 -> 0x05 -> 0x06 -> 0x07` 轮询并核对物理遮挡位置。
5. 对每块板分别遮挡五个通道，记录通道序号、实际朝向、距离有效率和盲区。

当前只确认了“四块阵列板的位置旋转 180°”。每块板内部五个超声波通道的
左到右顺序、波束朝向和遮挡关系本轮没有逐通道实测，状态为 **未确认**。

## 4. 详细验证记录

### 4.1 整车 CAN FD

当前总线为 11 位标准 ID、500 kbit/s 仲裁段、4 Mbit/s 数据段、ISO CAN FD、
BRS。60 秒只读监听结果：

| CAN ID | 节点/内容 | 帧数 | 实测频率 | 长度 |
| --- | --- | ---: | ---: | ---: |
| `0x181` | 电机状态 | 600 | 10.000 Hz | 32 B |
| `0x182` | 磁导航 TPDO1 | 6005 | 100.083 Hz | 48 B |
| `0x183` | BMS TPDO1 | 60 | 1.000 Hz | 32 B |
| `0x381` | 电机里程计 | 2999 | 49.983 Hz | 24 B |
| `0x481` | 电机安全状态 | 600 | 10.000 Hz | 16 B |

全网共 10264 帧，预期 ID 无缺失，长度异常 0、FD/BRS 异常 0、CAN 错误帧
0、磁导航序号跳变 0。原始记录见
[`canfd_vehicle_4m_validation_2026-08-15.md`](canfd_vehicle_4m_validation_2026-08-15.md)。

### 4.2 BMS 拔充电器连续供电

BMS 最新固件保留放电通路连续性修复：充电器插拔只改变 SC8815 充电功率级
请求，不在 BQ `CHG/DSG` 目标未变化时重写主 FET；放电条件持续满足时始终保持
DSG。现场测试步骤和结果：

1. 充电器接好时确认 `AC=1`、VBUS 约 24.2 V、充放电允许、BQ `CHG/DSG=1`。
2. 连续监听整车 CAN FD 后拔掉充电器。
3. 40 秒窗口内五类 PDO 完整，CAN 错误帧 0，BMS `0x183` 保持 1 Hz。
4. 用户确认所有板卡电源灯不再闪灭或重启。
5. 拔出后串口确认 `AC=0`、`charging=0`、放电允许、BQ `CHG/DSG=1`，保护位为 0。

代码证据：
[`bms/App/App_Power.c`](../../bms/App/App_Power.c)；BMS CAN FD 记录：
[`bms_canfd_vehicle_4m_validation_2026-08-15.md`](../../bms/docs/test/bms_canfd_vehicle_4m_validation_2026-08-15.md)。

### 4.3 四路防撞输入

硬件和位定义：右 `PB9/0x01`、左 `PC13/0x02`、后 `PC14/0x04`、前
`PC15/0x08`；外部 10 kΩ 上拉，开关闭合接地，所以低电平有效。代码证据：
[`bumper_input.c`](../src/bumper_input.c) 和 [`bumper_input.h`](../src/bumper_input.h)。

无电机输入测试从 `0x00` 开始，依次捕获：

```text
RIGHT -> 0x01
LEFT  -> 0x03
FRONT -> 0x0B
REAR  -> 0x0F
```

四个方向位全部出现，CAN 错误为 0。四路释放后发送
`CMD,CLEAR_FAULT,1,65001`，串口返回：

```text
ACK,65001,CLEAR_FAULT,RECEIVED,0
ACK,65001,CLEAR_FAULT,ACCEPTED,0
```

随后 `0x481` 连续 30 帧均为 `bumper=0x00`、`sources=0x00`、`safety=0`、
`fault=0`、`warning=0`，CAN 错误为 0。这同时验证了按下锁存、释放检测、
100 ms 稳定释放条件和显式清故障路径。

### 4.4 右轮反馈符号修复与闭环复测

首次低速架空测试中，左右目标均约 `+11.23 RPM`，左轮反馈约 `+12 RPM`，
右轮反馈却达到约 `-36 RPM`，右侧 PWM 持续增加并最终触发运动故障 `0x0004`。
用户现场确认右轮机械方向实际会使车辆向车头前进，因此不修改电机输出方向，
仅将
[`MOTOR_SPEED_RIGHT_FEEDBACK_SIGN`](../src/motor_speed_calibration.h)
从 `+1.0f` 改为 `-1.0f`。

修复后的构建和烧录结果：

- Keil ARMCC 5.06 update 7 build 960：`0 Error(s), 0 Warning(s)`。
- BIN：53268 Byte。
- SHA-256：`DCD857AEB796E22980303FF557F94CFF84BD82A67AC96D57A5396B6EE3A3F709`。
- ST-Link 使用 100 kHz SWD 和官方 `AT32F456_256.FLM`。
- 首次 FLM 初始化超时后按既有流程执行 `reset halt`，随后完整重试成功。
- 最终标志：`FLASH_VERIFY_OK bytes=53268`、`RESET_RUN_OK`。

复测使用 `GOTO 3000 mm / 50 mm/s`，两侧目标均约 `+11.23 RPM`。稳定阶段左侧
约 `+11.1 RPM`，右侧约 `+11.5 RPM`，两侧反馈同号且接近目标；2.2 秒后发送
STOP，任务正常取消，未再触发 `MOTION_ERROR`。

### 4.5 右侧防撞动态安全链路

修复右轮反馈后，车辆架空、两轮以 50 mm/s 指令低速运行。右侧防撞条触发后：

- `0x481`：`bumper=0x01`、`sources=0x01`、`safety=2`、`fault=0x00000008`。
- `0x181`：活动任务变为 0，进入防撞错误状态，故障保持 `0x00000008`。
- 从接收到右侧安全事件到下一帧状态确认约 71 ms；这是 CAN 状态确认时间，
  **不是机械停止距离或机械制动时间**。
- 串口状态：左右目标转速为 0，左右 PWM 为 0，状态为 `BUMPER_ERROR`。
- 任务启动后的 CAN 错误为 0。

软件链路已满足“本地碰撞 -> 取消任务 -> 主动制动命令 -> 锁存故障”。用户原计划
用视频记录车轮物理停止，但在本文提交前尚未明确回复视频观察结果，因此物理停止
结论保持为“人工待确认”。

## 5. 已知诊断限制

当前控制器进入 `HOLD`、`MOTION_ERROR` 或 `BUMPER_ERROR` 后会将目标转速和 PWM
清零并主动制动，但串口 `POSE` 和 CAN `0x381` 中的实测 RPM/线速度可能保持为
进入停止状态前的最后一次滤波值。该冻结值不表示 PWM 仍在输出。

因此停车判定必须同时检查：

1. 安全状态和故障来源正确；
2. 活动任务已取消；
3. 左右目标转速均为 0；
4. 左右 PWM 均为 0；
5. 视频或现场确认车轮物理停止。

后续应修正停止状态下的反馈刷新或遥测有效标志。在修正前，禁止仅以冻结的
`linear_mm_s` 判断防撞制动失败。

## 6. 当前硬件安全状态

本文编写时，电机板已因右侧防撞测试进入 `BUMPER_ERROR`，故障为 `0x0008`，
活动任务为 0，左右目标和 PWM 均为 0。控制器不会自动恢复原运动任务。

继续测试前必须确认四路防撞全部释放并稳定至少 100 ms，再显式发送
`CLEAR_FAULT`；清除成功后也必须重新发送新的低速运动命令。

## 7. 后续验收顺序

1. 回看右侧防撞视频并明确记录物理停止结果。
2. 车辆继续架空，依次对左、后、前执行独立动态制动测试；每一路之间必须先
   释放、清故障、确认全 0，再重新启动。
3. 单板连接四块 GD32 超声波阵列，按第 2 节重新写入非易失位置和节点地址。
4. 四板接回 RS485 后，逐地址读取身份和五通道距离，并用实体遮挡核对物理方位。
5. 保存 60 秒四板动态 CSV，检查地址冲突、CRC、超时、有效率和串扰。
6. 完成上述项目后，才进入落地低速、带负载 PID 和整车障碍物联动验收。
