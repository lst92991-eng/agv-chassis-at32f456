# L型磁道回充模拟完整流程实车验收（2026-08-21）

## 1. 验收目标

本轮把此前分散验证的能力串成一条可观察的整车流程：

```text
L型磁道起点
  -> 循磁前往末端
  -> 后退150mm
  -> 原地左转180°，车尾朝向充电桩
  -> 单红外接收头有限角度主动扫描
  -> 转到38kHz红外信号峰值方向
  -> 稳定保持3秒，模拟充电完成
  -> 恢复磁道返航航向
  -> 循磁返回起点
```

本轮“模拟充电”只验证任务时序和红外稳定证据，没有电极接触、充电电流或BMS充电
状态，因此不能写成真实自动充电通过。双TOF已经由低优先级任务采集并通过`0x582`
上报，但120°V形靶标下的接触基准仍未标定，本轮不让旧的43/26mm基准驱动车辆接近。

## 2. 环境与硬件

- L型磁条：起点直段约1.4m，转弯后长段约3.2m，弯角为可弯曲磁条形成的圆滑90°；
- 车辆落地，底盘X轴向车头、Y轴向左、Z轴向上；
- 电机板：AT32F456RCT7，ST-Link连接；
- CAN FD：500kbit/s仲裁、4Mbit/s数据、BRS，USB-CAN连接；
- BMS和整车CAN网络在线；
- 充电桩持续发射38kHz红外，车尾IRM-H238T接收；
- 超声波阵列本轮为断开/监视模式，四路防撞、BMS禁止、CAN租约、IMU、磁条丢失和
  任务超时仍保持板端保护；
- 操作员全程观察，并保留防撞条作为最后人工停车手段。

## 3. 问题演进与根因

### 3.1 直线被误判为弯道

早期策略仅凭小偏移和目标Yaw判断曲线，2~3mm量化抖动会把车辆长期锁在75mm/s。
修正后要求横向偏差向外增长，或实际BMI270角速度与目标转向同向，再以连续样本确认；
稳定居中300ms后才进入高速直线。

### 3.2 返程两次撞柜

第一次修正仅把磁循迹的速度上限从高速改为150/75/50mm/s，但控制器对下降目标仍使用
`0.75RPM/样本`的软件斜坡；即使弯道已识别，从330mm/s降到75mm/s仍需数秒。

将动态限速改为“弯道确认当帧生效”后，电机实测仍降得太慢。日志显示目标轮速已降到
约20/2RPM时，实际仍约68/68RPM，PWM仍保持约953/755。最终根因不是PI判断错误，而是
PWM加减速共用`12 PWM/20ms`的对称斜率，旧动力需要约1.3秒才能撤掉。

最终采用非对称斜率：

- 增加动力：12 PWM/20ms，保持平顺；
- 撤减动力：80 PWM/20ms，弯前约0.2秒撤掉旧PWM；
- 不使用反向PWM强刹，电机速度环继续负责实际减速。

### 3.3 固定4.6m与人工摆车不一致

返程实际行驶约4.18m后到达起点磁条物理末端，用户确认车辆已正常返回。旧逻辑只允许
目标末端最后150mm出现无磁，因此把正常到站误报为磁条故障。人工摆车会覆盖约20~30cm，
固定绝对里程不适合作为唯一终点条件。

最终规则为：连续无效10个控制周期时，若已进入目标路程最后10%，则正常完成；该窗口
限制在50~500mm。更早丢磁仍立即制动并锁存磁条故障。对本次4.6m任务，正常终点窗口为
460mm，覆盖实测约420mm差值，同时不会把路线中段丢磁当成成功。

## 4. 最终控制参数

| 项目 | 最终值 | 说明 |
| --- | ---: | --- |
| 直线任务请求 | 250mm/s | 本轮完整流程上限 |
| 弯道可疑上限 | 150mm/s | 外偏趋势或实际Yaw证据出现 |
| 已确认弯道上限 | 75mm/s | 圆滑L型主转弯速度 |
| 紧急大偏差上限 | 50mm/s | 偏差达到9mm等紧急条件 |
| 高速进入条件 | 居中稳定300ms | 起步先低速捕获磁条 |
| 上位机起步偏差 | ±20mm | 底层有效边界仍为±35mm |
| PWM上升斜率 | 12/20ms | 保持柔和加速 |
| PWM下降斜率 | 80/20ms | 快速撤掉旧动力 |
| 物理终点窗口 | 目标10%，50~500mm | 只改变到站结果，不取消丢磁停车 |

固件协议仍允许不超过330mm/s的磁循迹请求，但本L型道路的当前验收峰值固定为250mm/s；
330mm/s不再作为这条无RFID、无提前弯道标记路线的通过条件。

## 5. 实车过程与数据

### 5.1 去程、后退和掉头

- 启动偏移约`-3.2~-3.9mm`，磁强度约`1040~1075`；
- 直线稳定速度约`238~251mm/s`，个别10Hz里程计帧出现`277~284mm/s`瞬态；
- 首个弯前约`238mm/s`，识别后约0.5秒降到`91mm/s`，随后以约`50~80mm/s`
  完成圆滑90°转弯；
- 去程4600mm任务成功；
- 后退150mm任务成功，实测约`-41~-48mm/s`；
- 300mm/s参数的180°原地旋转成功；
- Supervisor记录`tx=721`、`tx_fail=0`，阶段结果为`CONTROLLED_TEST_PASS`。

### 5.2 红外峰值扫描与模拟充电

单接收头没有直接方向信息，因此必须主动改变车身角度并比较100ms窗口证据。扫描结果：

| 相对角度 | 得分 | 活动窗口 | 累计边沿 |
| ---: | ---: | ---: | ---: |
| 0° | 250 | 8/11 | 47 |
| +10°（第一次） | 444 | 9/10 | 80 |
| +20° | 292 | 6/10 | 66 |
| +30° | 0 | 0/11 | 0 |
| +10°（回扫） | 600 | 9/11 | 110 |
| -10° | 52 | 5/10 | 13 |
| -30° | 256 | 6/10 | 59 |

算法选择`+10°`为峰值方向。保持3秒时，30个窗口中24个有效，累计261个下降沿，
`SIMULATED_CHARGE_PASS`。随后反向旋转10°恢复磁道返航航向。

本次主动扫描由电脑端调试编排调用正式有界运动命令完成；数据证明扫描策略有效，但该
编排尚未合入未来RK3576上的C++ Supervisor正式任务，不能把它写成电机板自主回充。

### 5.3 返航

- 起步偏移约`-10mm`，无需人工绝对居中，低速捕获后自动回正；
- 返程右转前约`243~274mm/s`；发现弯道后约0.27秒降到`80mm/s`，随后约
  `45~78mm/s`完成此前两次撞柜的右转；
- 本轮右转没有碰撞、没有防撞触发，弯后重新加速至约`240~251mm/s`；
- 返程实际约4.18m后驶出起点磁条，板端立即停车；故障位为磁条`0x0040`，上位机退出
  后叠加通信超时成为`0x0050`，没有防撞位；
- 操作员确认车辆已正常到达起点，完整物理路线通过；随后将终点判定修正为目标10%。

## 6. 构建、烧录与回归

- 编译器：Keil ARMCC 5.06 update 7 build 960；
- 结果：`0 Error(s), 0 Warning(s)`；
- BIN：79,552 bytes；
- SHA-256：`5BC1E68E7962B8F129DA02829276F6DA5598DCDEEFA195F5F97DD43B8F6DBF02`；
- 主机测试：航向融合、磁循迹控制、CAN FD状态PDO编码全部通过；
- 上位机工作区9项C++测试全部通过；
- 本轮实车运行版本为79,460 bytes，SHA-256为
  `6A29F9C6031AD01A68B8C56D837361CF8F798A1AA91183A97FDE1E9B1CAC2E5C`，ST-Link
  逐扇区擦除、逐页编程和整BIN校验返回`FLASH_VERIFY_OK`；
- 最终79,552-byte BIN包含实车返回后补充的动态终点窗口。提交前重试烧录时系统已
  无法枚举ST-Link，OpenOCD在擦除前返回`open failed`，因此该最后一项变更处于
  “已回归、已编译、待下次连接补烧”状态，板上仍是前述实车运行版本。

最终动态终点窗口是在本轮实车返回后依据已记录的4.18m路径补充，已完成主机回归和
Keil构建；下次连接ST-Link后补烧并静态确认`IDLE / fault=0`即可，无需再次用柜子
附近的相同风险场景验证停车。

## 7. 验收结论与剩余边界

本轮通过：

1. 250mm/s级直线、弯道自动降速和双向L型循迹；
2. 150mm后退、180°掉头和磁条重新捕获；
3. 38kHz红外接收、有限角度峰值扫描和3秒模拟充电；
4. 返回起点，且此前右转撞柜问题不再出现；
5. 防撞、磁条丢失、CAN租约等板端安全链路始终保留。

仍未通过：

1. 120°V形靶标下双TOF接触基准和对齐方向标定；
2. 红外峰值扫描接入正式C++ Supervisor整车任务；
3. 电极真实接触、充电桩会话和BMS充电电流三方确认；
4. 完整任务20次重复性、不同初始偏置和不同电量下的统计验收；
5. 330mm/s无标记L型转弯。若未来需要，只能增加路线记忆/提前减速，不能继续依赖
   弯道出现后再临场急刹。
